## День 5: Практика (Диагностика инцидента)

**Проблема:** Сервис на порту 9999 возвращает `Failed to connect`.
**Важный нюанс:** В начале диагностики порт 8080 был занят старым Tomcat, что сбило с толку. Это частая ситуация в работе: порт может быть занят другим процессом.

**Шаги расследования на порту 9999:**
1. `ss -tulnp | grep 9999` -> пусто, порт свободен.
2. `docker ps` -> контейнер `broken-app` работает, но в колонке PORTS только `80/tcp`.
3. `curl -I http://localhost:9999` -> Failed to connect.
4. `docker logs broken-app` -> логи чистые, Nginx внутри работает.

**Причина:** Контейнер запущен без проброса портов (`-p`).
**Решение:** `docker rm -f broken-app` и запуск `docker run -d -p 9999:80 --name fixed-app nginx`.
**Результат:** `curl -I http://localhost:9999` возвращает `200 OK`.
